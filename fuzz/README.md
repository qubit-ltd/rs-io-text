# Fuzz targets

`charset_stream` exercises the synchronous charset stream paths. `async_charset_state` drives the asynchronous charset reader and writer with four header-selected scenarios: writer progress and finish, character batches, line reads, and limited-line reads with rejection recovery.

The asynchronous target caps each input at 4096 bytes. Six header bytes select the scenario, capacity (1–8), line-ending set, operation count, event count, and poll/cancellation parameter. The operation and event count bytes are each reduced modulo 65, selecting 0–64 bytes; the target then reads up to that many operation bytes, up to that many scheduled I/O events, and uses the remainder as payload. The four original scenarios retain their meaning: writer progress/finish, character batches, normal lines, and limited lines. Those scenarios still convert payload bytes to valid source text with lossy UTF-8 conversion.

After the selected legacy scenario, the target runs at most one independent raw-byte reader companion on the original payload. It never uses the lossy text as this reader's input. `scene % 3` selects Report, Replace (default U+FFFD), or Ignore; Report always reads one character at a time so decode errors cannot be confused with limited-line errors. For Replace and Ignore, `endings % 3` selects character/batch reads, normal-line reads, or limited-line reads, while `line_ending_set(endings)` still selects the configured line endings. The companion receives a copied event schedule and its own input position. A standard-library `from_utf8` segmented reference model computes expected output and the first malformed-byte offset; valid U+FFFD characters remain ordinary text. Report stops on the first non-injected decode error and never retries it. Replace/Ignore check complete output at natural EOF, including records formed when ignored bytes join CRLF. Limited reads use decoded UTF-8 byte lengths and retain the existing per-call limit and rejection recovery checks.

In each scenario, record reads use the selected line operation. In limited-line scene 3, each record uses its corresponding operation byte modulo 33 as the per-call append limit (0–32 bytes); missing operation bytes mean zero. Retries of a record keep the same limit, while a retained prefix from an earlier call does not reduce the next call's allowance. The scene checks target prefix preservation, rollback on rejection, and natural EOF completion. Writer operations choose a single string step, character-slice step, explicit flush after a step, or entry into finish. Readers receive the full event schedule; writer events at even original positions feed write and odd positions feed flush, so events are never cloned. A nonzero cancellation setting drops a Future at a Pending poll and retries that operation on the same adapter. Pending and injected I/O errors do not transfer data. Errors are retried only when their source is the model's `InjectedFault`.

Each reader scenario (legacy and raw companion) is bounded to 64 logical operations, 64 I/O events, and 65,536 polls. Event schedules become ready after their finite events are consumed. The model checks accepted/delivered writer prefixes and reader prefixes when the operation budget ends; when a reader observes natural EOF, it requires the complete expected text, records, or rejected-record count. Deterministic unit tests assert malformed middle/tail input, all policies and read modes, cancellation, injected errors, and rejection recovery branches. A fuzz smoke run alone is not a coverage claim.

Run a deterministic smoke from the repository root:

```sh
cargo +nightly-2026-06-05 fuzz run async_charset_state -- -max_total_time=10 -max_len=4096 -seed=1
```

When fuzzing finds a failure, preserve the input and seed, minimize the input, then convert the reduced case into a focused regression test.
